# IP reputation before DATA

NoiseFence queries configured IP DNSBLs configured after validation of at least one recipient, before the `354` response, body storage and acquisition of an analysis capability. A refusal at this stage avoids OCR, antivirus, models, redirects and reputation API. In observation, these analyses continue: no content saving or improved capture rate is claimed.

Only the IP of the TCP connection is used. A `Received`, a HELO, a sender or a `X-NoiseFence-*` header provided in the message cannot replace it. Private and reserved IPs are ignored; placing a SMTP proxy in front of this listen therefore loses the reputation of the original peer. No PROXY protocol or implicit trust header is accepted.

## Configuration

Without lists or DQS keys, no DNSBL calls are made. Spamhaus integration uses the variable already declared in `[filter].spamhaus_key_env` and adds ZEN to the early controls. Disable "Reputation" in the console also disables this ZEN control. Manage additional lists, codes, actions, timeouts and cache limits in **Filters → IP reputation · RBL**. Reviewed revisions apply to new transactions without restarting; these lists have their own enabled switches.

```toml
[rbl]
action = "observe"          # observe, defer (451), reject (550)
minimum_providers = 2       # 1 to 8 distinct operators
timeout_ms = 800            # overall budget; 10 to 2,000 ms
max_parallel = 8            # active DNS queries shared across connections
cache_entries = 4096        # 1 to 16,384 entries
cache_ttl_seconds = 60      # upper bound; never extends the DNS TTL

# Fictitious example: replace with an authorized IP list and its documented return codes.
[[rbl.lists]]
id = "provider_a_ip"
provider = "provider_a"
zone = "dnsbl.provider.example"
listed_codes = ["127.0.0.2"]
observe_codes = ["127.0.0.10"]
ipv6 = false               # true only if the provider supports IPv6
# key_env = "PROVIDER_A_DNS_KEY" # reversed-IP.key.zone query when required
```

The same `provider` must identify all the lists of the same operator: two zones of this operator are only one vote. A single list with the default threshold produces observations, without refusal. Spamhaus areas are reserved for the DQS connector to keep the interpretation of their categories and errors. Other providers' codes are exact IPv4 addresses, without mask or bit logic; fill in all documented combinations or not use an incompatible list. Never enter error codes in `listed_codes` or `observe_codes`.

To apply a refusal, use `filter.mode = "enforce"`, an action RBL `defer` or `reject`, enough positive suppliers and no result unavailable. `observe` or `tag` mode always requires observation, regardless of the RBL action requested. Existing configuration and delivery validations remain required. Unknown recipients remain refused separately.

The `451`/`550` refusals occur before SMTP acceptance: no message is filed and no notice of failure is generated by NoiseFence. The transmitter processes the SMTP response. After refusal, a new transaction requires `MAIL` and `RCPT`. `defer` is a temporary refusal of reputation, **not greylisting**: there is no delaying of a triplet sender/recipient/IP or an automatic transit list on the second trial. Existing limits of connections, IP connections and analysis concurrency remain independent; no hourly quota is added here.

<a id="résultats-limites-et-faux-positifs"></a>
## Results, limitations and false positives

- Only NXDOMAIN means "not listed". NODATA, SERVFAIL, REFUSED, timeout, unexpected response or mixing valid codes and error codes are unavailable. An unlisted IP is not proof of legitimacy.
- ZEN SBL/CSS/XBL/DROP is a vote; PBL and BCL remain observations without a vote. These categories and codes are checked in the existing connector.
- IPv4 uses inverted bytes, IPv6 the 32 inverted hexadecimal digits. IPv4 addresses mapped in IPv6 are standardized. Each request requests A records even for IPv6, with a 32-response limit.
- Queries are simultaneously advanced within a global time frame, without detached application task. Saturation makes control unavailable immediately. The cache is usable even when all DNS capabilities are occupied. Errors received are stored for one second as unavailable; a timeout is not stored. Invalid positive/negative TTLs are not prolonged.
- Provider TXTs are neither displayed nor interpolated in SMTP. Reports contain only logical names of lists, codes, availability, duration, cache and action. Queries containing a key are never logged by this module; avoid DNS debugging logs from the solver on a keyed service.

The `early_rbl` report is attached to the accepted messages **after** the calculation of the decisions: it does not change score or completeness and does not double the existing ZEN weight. ZEN control after DATA is retained, with its own cache and verification: a long DATA transfer may have exceeded the observed TTL before receiving. DBL, the body domains and URL destinations remain checked after receiving. A URIBL of domains should not be configured as an IP DNSBL.

`SMTP early RBL check` also keeps refusal decisions, which do not appear as messages in the console since no bodies have been accepted. The accepted message sheet displays the checks before receipt, within the usual rights perimeter. The retention of metadata remains for 30 days and the current installation’s storage schema applies.

## Check without sending email

```sh
noisefence --config /etc/noisefence/config.toml rbl-check \
  --source-ip 8.8.8.8 --iterations 3
```

This command does not open file or model and does not send any messages. It performs real IP queries from the only configured lists; check the right of use, the solver and the supplier's quotas beforehand. It uses the effective saved policy when one is present. Also test a positive public IP and a negative public IP provided by the operator, then observe a recent and annotated sample before any refusal application.

Automated tests use only deterministic responses and local sockets, with control of DNS errors, cache, delays, codes, consensus, observation delivery and refusal before storage/analysis. They do not measure the coverage of a list of real traffic.

This feature’s original migration was additive. Current paired installations require storage schema 5 and a compatible release. Do not downgrade the database, remove its HA marker or restore an older backup over accepted mail. See [installation](installation.md) and [HA recovery](high-availability.md) for current upgrade and rollback procedures.
